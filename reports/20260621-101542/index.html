你脚下那把枪,叫 harness

你问的是:harness 到底是什么、边界在哪——提示词和 skill 我都熟,可 CLI、harness、agent 这几个词,我分不清。而这一问真正在赌的,是作为做京小贝的产品人,你该把团队工程力押在哪一层。

总判断

模型、提示词、skill、harness、CLI、agent 不在一条起跑线上,它们是上下叠着的一座塔;harness 就是托着模型跑的那层「身体」,你最熟的 prompt 和 skill 只是喂进它嘴里的子弹。而护城河不在 harness 那层——它是 Anthropic 在守、还在亲手填平的城;京小贝真正的金矿,在用户每天替你挖出的独家数据,和你用合规砌起的那道墙里。

1

六个词不是对手,是一座塔

带回的判断

这六个词压根不在一条起跑线上,没法比——它们是上下叠着的一座塔。harness 是托着模型跑的「身体」,prompt 和 skill 不是塔里的硬件,是喂进它嘴里的内容;你三个 agent(Claude Code / OpenClaw / Hermes)都站在 harness 这一层,只是换了张脸、接了颗脑。

最底是模型:云端那颗大脑,给它一段文字、吐回一段文字,没手脚、没记忆、不会自己循环。套在它外面的第 2 层就是 harness——一个一圈圈转的循环(agent loop):拼上下文、调模型、接住模型说「我要用某工具」并真去执行、把结果塞回上下文、再管窗口别撑爆和权限。最外面第 3 层是入口皮:CLI 命令行、IDE 插件、网页、飞书、微信——同一个身体可以换不同的脸,换脸,身体一点没变。你每天念叨的 prompt 和 skill 不是塔里的硬件,是喂进这个身体嘴里的内容。

你的三个 agent 都站在第 2 层:Claude Code(脸=CLI/IDE,脑=Claude,专攻编码)、OpenClaw(脸=飞书/微信,可换多模型,管日常对话与知识库)、Hermes(脸=飞书,喊 claude -p 当脑,在你这套墨菲斯里更瘦、兼一层薄传输)。而 「agent」本身不是塔里的某一层,它是模型+harness+入口装在一起、能自己干活的那整套成品的名字。

你 Hermes 的特殊性,在你自己代码里被白纸黑字写成「薄传输+路由,把脑外包给 claude -p 子进程」——这是你机器上「Claude 当脑、Hermes 当身体」的实物证据,不是我猜的。 scripts/morpheus_think.py · specs/003-claude-brain-research/plan.md
反面 / 风险

OpenClaw 的分层归类(harness / 身体)是基于其已知功能做的架构推断,这个具体产品没有公开资料可引。Hermes 那条相反——有你自己的项目代码作硬证据。

2

模型说完一句就死了

带回的判断

模型有个死穴:给它一句话,它「想」完一步就死了,连刚才说了啥都不记得。是 harness 独占的一对孪生控制权——「一圈圈重跑」和「每圈往模型嘴里写什么」——把它一次次救活;agent 能自己把活干完,就从这对权力里长出来。

模型的全部本事,是「喂它一坨文字、算一遍、吐一坨文字」。算完这次调用就结束,它什么都不记得,连「我再想一步」都做不到,因为「再来一次」根本不在它能力里。那 Claude Code 怎么一口气读五个文件、改代码、还说「先跑个测试」?把「读一下 plan.md」这一回合慢放:harness 先把整坨(系统设定 + 所有工具长啥样 + 历史对话 + 你这句)拼齐发过去;模型吐回的不是文件内容——它没读过任何文件,它吐的是一张纸条「我想用 Read 读 plan.md」,吐完就死;harness 接手,过一道权限闸(读文件放行,要删库就在这儿拦你确认),真的去操作系统里把文件捞出来;再把文件内容塞进下一圈的输入、把模型叫醒;模型这才基于内容吐下一步。整回合模型只露两次面,每次都「吃一坨、吐一坨、然后失忆」——把它们串起来、决定每次喂什么、判断何时收手,全是 harness 干的。

harness 补给模型的最核心那一件事,是它独占了一对孪生的控制权——「一圈圈重跑(循环)」和「每圈往模型嘴里写什么(进料口)」。聪明在模型里,能干活这件事在 harness 里。 Anthropic 官方 tool use 文档 · platform.claude.com
3

一条线,一刀切清边界

带回的判断

谁握着循环、并握着「往上下文窗口里写什么」的权力,谁就是 harness。拿这把尺子量:往下,模型不算(分界就在那一次 API 调用上);往上,CLI / 网页 / 飞书是「皮」;往旁边,MCP / 工具 / skill 是「外挂」。

这条线简单到你会怀疑,但够用。往下:模型不算 harness——调用之内(把字发给云端、拿回答案)是模型的活,调用之外那个一圈圈转的循环是 harness 的活。往上:CLI / 网页 / 飞书是皮——同一套 harness 从终端进、从网页进、像你这套从飞书进,循环逻辑一个字不用改;能被整块换掉而内核不动的,按定义就不是内核。往旁边:MCP / 工具 / skill 是外挂——MCP 官方自己声明,它只管工具和数据怎么标准化地递进来,明确不规定怎么用模型、怎么管上下文,等于把「循环+上下文写权」原封不动留给了 harness。那几个灰色地带(system prompt 怎么拼、记忆回填哪几条、子 agent 拆几个各喂什么)一量就清楚:全是「在循环每一拍决定往那屏字里写什么」,全是握笔的手,全是 harness 内核。

对你团队的直接落点:内核(循环、上下文拼装、记忆选取、子 agent 编排)重投工程力;外挂(MCP / 工具 / skill)主要接标准、接口做干净、别造轮子;皮(CLI / 网页 / 飞书)做多端适配、别让某个入口把循环绑死。

谁握着那支笔——谁拥有「循环」、并拥有「往上下文窗口里写什么」的权力,谁就是 harness。 MCP 官方架构与边界声明 · modelcontextprotocol.io
反面 / 风险

「harness」业界没有标准组织的统一定义(也叫 agent runtime / scaffold)。这条「谁握循环+上下文写权,谁就是 harness」的切分线,是综合多个权威来源后的判断、不是某份规范的原文——但它和所有来源自洽,且能干净处理灰区。

4

agent 是整栈成品,不是某一层

带回的判断

「agent」有两层意思:大的是「整个系统在跑」,小的是「系统跑途中临时开的一个隔离、干净的第二个上下文窗口」。子 agent 的本质,就是那个隔离开的、干净的第二个上下文窗口——看懂这层,任何「多 agent 编排」都褪去术语,变成一个总编带一群记者。

这堆词里 agent 歧义最大:一会儿指整个跑起来的系统,一会儿指你用 Task 派出去的小兵。其实是同一结构的两个尺度。广义 agent=一个模型 + 一套工具 + 一个目标,在循环里自己决定下一步(而非照写死的剧本走),你的墨菲斯 worker 整体就是。子 agent=主系统干活中途临时雇的「带独立脑子的临时工」,本质就是再开一个空白、干净的第二个上下文窗口,塞给它子任务,它在那窗口里翻江倒海,跑完只递回一句结论,然后回收。

为什么要这么干?一个 agent 一次能看进眼里的全部东西(查过的网页、读过的文件、纠结过的废稿)全挤在一个有限的上下文窗口里;让它自己顺着查 5 个问题,盒子很快被中间垃圾塞爆、对全局的判断力就糊了。子 agent 一招治两病:主 agent 的盒子永远干净(只拿回结论、不沾垃圾),临时工还能 5 个一起并行。

你的 morpheus-worker 写死了「必须组建专家团队,严禁单干」。这 5 个问题各派一个专家(子 agent),在各自干净的盒子里联网、钻研、试错,我(总编)只攒回 5 份干净判断——一个总编带一群各有独立脑子的记者,这就是「多 agent 编排」褪去术语后的真身。 Anthropic《How we built our multi-agent research system》
5

护城河不在你以为的那层

带回的判断

harness 这层确实值钱(光改架构,SWE-bench 能涨 22 分,换模型只涨 1 分),但这条护城河是 Anthropic 的、不是京小贝的——官方已把 harness 打包成免费 SDK、把 MCP 捐给 Linux 基金会,昨天的护城河今天变成免费水泥地。给京小贝的押注:接标准 harness,重押独家数据,合规即护城河,吃满京东分发。

模型谁都能调,Claude Code、Cursor、Codex 底下那台发动机其实差不多,它们卷的是发动机外面那套传动系统——harness。这层真值钱:同一个模型,光改 harness 架构,SWE-bench 上能改 22 分,换一代新模型只改 1 分。所以 2026 全行业都喊「模型是燃料,harness 才是护城河」。但这正是要拆穿的地方。

反转一:这条护城河是 Anthropic 的,不是京小贝的。官方把自己最值钱的 harness 打包成谁都能免费装的 Claude Agent SDK,又把接工具的 MCP 捐给了 Linux 基金会(OpenAI、谷歌、微软一起站台,变成像 USB 口一样的公共标准)——昨天的护城河,今天被官方亲手填平成所有人脚下的免费水泥地。它对造模型的实验室仍是护城河(模型针对自家 harness 调教、协同进化),可你不造模型,拿到的只是被免费送给你、也送给豆包的公共品。

反转二:护城河迁到哪了?不在 prompt / skill 那层。prompt 和 skill 是世界上最容易被复制的东西,你写的金融话术豆包照样写。它迁到了两处:其一,你的产品独家「制造」出来的数据——用户在京小贝面前暴露的真实财务状态、面对涨跌的反应、被哪句话说服,只有当用户把它当成管钱的记录系统(system of record)才会被生出来,通用大模型这辈子拿不到;其二,金融这行的合规边界本身就是墙,「算得对、说得清、过得了监管」才值钱,这道墙挡的不是用户,是竞争对手。

押注方向:别去自建通用 harness(那是在 Anthropic 有结构性优势、还在把成本打到零的战场上砸重资产);站在标准 harness 上,把团队工程力全压在三件事——① 数据飞轮(最高优先级):把京小贝做成京东金融用户财务的记录系统;② 金融 skill 和合规焊死、可审计、过监管;③ 吃满京东分发,把 agent 深度嵌进现有工作流。

接标准 harness,重押独家数据,合规即护城河,吃满京东分发。harness 是地图上一座别人在守的城;真正属于你的金矿,在你脚下用户每天替你挖出来的那堆数据里。 段永平 / a16z 框架 · a16z.com/is-software-losing-its-head
反面 / 风险

「通用 harness 长期沦为 commodity」是趋势推断、不是定论——方向证据硬(官方 SDK + MCP 标准化 + 可热插拔 harness 三箭齐发),但沦为 commodity 到什么程度、多快是推测。「对应用层=commodity、对实验室=护城河」这个区分,是墨菲斯的判断,不是哪篇文章的原话。
