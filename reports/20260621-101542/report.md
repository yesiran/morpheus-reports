# 你一直在打磨子弹,却没人指给你看脚下那把枪——它叫 harness

## 先给你一个能直接拿走的判断

你每天念叨的这六个词——**模型、提示词、skill、harness、CLI、agent**——你一直把它们当成六个在抢地盘的对手:纠结"我该上 skill 还是上 agent""命令行(CLI)和 harness 谁更底层"。

**反常识的真相是:它们压根不在一条起跑线上,没法比。它们是上下叠着的一座塔。**

而其中那个让你"分不清"的 harness,是这座塔里你**从没被命名过的那一层**——它是托着模型跑的"身体"。你最熟的 prompt 和 skill,根本不是塔里的一层硬件,它们是**喂进这个身体嘴里的内容**。打个比方你立刻就懂:**你是打磨子弹(skill)的老手,但一直没人指着你脚下那把一直在响的枪(harness)告诉你它叫什么。** 你那股"这些词被并排摆着"的别扭感,根源就在这儿——你把一发子弹和一把枪摆在了同一行里比大小。

这份报告干两件事:先把这座塔画给你,让你每天用的 OpenClaw / Hermes / Claude Code 各自归位(**方位**);最后那一题最硬,也最值钱——作为做京小贝的产品人,真正的护城河落在哪层、你该把团队工程力押在哪(**下注**)。**剧透一句先让你带着疑问往下读:护城河不在你以为的那层。**

## 一、先把塔画出来:谁套着谁

```
  喂进去的「内容」(不是塔里的一层硬件,是吃进嘴里的东西)
     · 提示词 / prompt   —— 你这一句话
     · skill            —— 一包预写好的指令+做法(本质就是一段很长、很讲究的 prompt)
     · 记忆 / 知识库     —— CLAUDE.md、case 文件、知识库
     · 工具返回的结果    —— 搜到的网页、读到的文件、命令的输出
              │  这些全流进 ↓ 同一个地方:模型的「上下文窗口」
              ▼
 ┌──────────────────────────────────────────────────────────┐
 │ 第 3 层 · 入口皮(你的手碰到的那张脸)                       │
 │   CLI命令行 / IDE插件 / 网页 / 飞书机器人 / 微信            │
 │   —— 同一个身体可以换不同的脸。换脸,身体一点没变。         │
 ├──────────────────────────────────────────────────────────┤
 │ 第 2 层 · harness = 运行循环层(★这就是那层「身体」·承重墙★)│
 │   一个一圈圈转的循环(agent loop),每圈干这几件:            │
 │     ① 拼上下文:把你的话+skill+记忆+上轮工具结果,组装好     │
 │     ② 调模型:把这一坨发给云端,问"下一步干啥"              │
 │     ③ 接住模型说的"我要用某工具",真的去执行                │
 │     ④ 把工具结果塞回上下文,进下一圈                        │
 │     ⑤ 管窗口别撑爆、管权限(能不能联网/写盘)、记账           │
 ├──────────────────────────────────────────────────────────┤
 │ 第 1 层 · 模型(云端 API,那"一颗大脑")                     │
 │   Claude / GPT / 豆包… 给它一段文字,吐回一段文字。          │
 │   没手脚、没记忆、不会自己循环。                            │
 └──────────────────────────────────────────────────────────┘
```

**你的三个 agent,三个都站在第 2 层(都是 harness/身体),区别只在换了哪张脸、接了哪颗脑:**

| 产品 | 它是哪层 | 第3层·脸 | 第1层·脑 | 侧重 |
|---|---|---|---|---|
| **Claude Code** | harness(身体) | CLI 命令行 / IDE | Claude | 编码:跑命令、改文件、连续干活 |
| **OpenClaw** | harness(身体) | 飞书 / 微信 | 可换多模型 | 日常对话、任务、维护知识库 |
| **Hermes** | harness(身体)+ 在你这套墨菲斯里更瘦,兼"薄传输" | 飞书 | 喊 `claude -p` 当脑 | 持续学习、自动生成 skill;动脑时把脑外包出去 |

这里有个最容易忽略、但一通百通的点:**"agent"这个词本身不是塔里的某一层**——它指的是"模型(第1层)+ harness(第2层)+ 入口(第3层)装在一起、能自己干活的那**整套成品**"。所以 agent 是**整栈的成品名**,不是和 harness/CLI 并列的兄弟。(这一点第四节会专门拆,它是这堆词里歧义最大的一个。)

> 顺手把你 Hermes 的特殊性钉一下:它在你自己的代码里(`scripts/morpheus_think.py`、`specs/003-claude-brain-research/plan.md`)被白纸黑字写成"薄传输+路由,把脑外包给 `claude -p` 子进程"——**这是你机器上"Claude 当脑、Hermes 当身体/传输"的实物证据,不是我猜的。**

*来源:Anthropic 官方把 agent 拆成"大脑/手脚"两件可独立替换的东西(anthropic.com/engineering/managed-agents);harness 定义见 huggingface.co/blog/agent-glossary。OpenClaw 的归类是基于"它是接飞书/微信、会用工具/记忆/连续干活的常驻 agent"做的架构推断——这个具体产品没有公开资料可引,我标清楚。*

## 二、往下看一层:模型为什么自己变不成 agent?

你可能会问:既然模型这么强,凭什么说它"自己什么都干不了"、非得有个 harness 托着?

**因为模型有一个你天天用却没盯着看的死穴:你给它一句话,它"想"完一步,就死了。**

这不是夸张,是机制。一个语言模型的全部本事,是"给它一坨文字,它算一遍,吐一坨文字"。算完这一遍,**这次调用就结束,它什么都不记得**——连"我刚才说了啥"都不知道。它连"我再想一步"都做不到,因为"再来一次"这个动作根本不在它能力里。

那问题就来了:你用 Claude Code,明明看见它一口气读了五个文件、改了代码、还说"我先跑个测试"——一个说完一句就死的东西,是**谁在背后一次次把它救活**的?

是 harness。我们用 Claude Code 跑"读一下 plan.md"这一个真实回合,慢镜头走一遍,你就看见那只手了:

1. **你以为发给模型的是"读一下 plan.md"——不是。** harness 把**整坨**拼齐发过去:系统设定 + 所有工具长啥样 + 之前的对话 + 你这句。(因为模型失忆,每圈都得从头喂全。)
2. **模型吐出来的不是文件内容——它吐不出来,它没读过任何文件。** 它吐出的是一张**纸条**:"我想用 Read 工具,读 plan.md"。吐完,这次调用结束,模型**死了**。
3. **harness 接手**(此刻模型完全不存在):它看懂纸条 → (过一道权限闸:读文件放行,要是"删库"就在这儿拦你确认)→ **真的去操作系统里把文件捞出来**。
4. **harness 行使它最关键的权力**:把刚捞到的文件内容,**塞进下一圈的输入里**,再把模型叫醒。
5. 模型这次的输入里有了文件内容,于是能基于内容吐下一步——可能"我看完了"(harness 收手),可能又一张纸条(再转一圈)。

看明白了吗?整个回合里,模型只露了两次面,每次都是"吃一坨、吐一坨、然后失忆"。**把这两次串起来、让结果接上下一次、决定每次喂什么、判断什么时候不用再喂——全是 harness 干的。**

所以这一题的判断,可以一句话带走:

> **harness 补给模型的最核心那一件事,是它独占了一对孪生的控制权——"一圈圈重跑(循环)"和"每圈往模型嘴里写什么(进料口)"。agent 能自己把活干完,就是从这对控制权里长出来的。聪明在模型里,能干活这件事在 harness 里。**

harness 不是包装纸,是**器官**。模型是"会想一步的脑组织",但让脑组织变成一个能自己把活干完的活物的,是循环系统加那张决定喂什么的嘴。

*来源:模型无状态、每次重传完整上下文(atlan.com/know/are-llms-stateless);模型不执行工具、只吐 tool_use 意图、harness 执行后回 tool_result、循环按 stop_reason 转——Anthropic 官方 tool use 文档(platform.claude.com);上下文满了自动压缩(auto-compact)是 harness 行使"写什么进窗口"权的实证(code.claude.com)。*

## 三、你点名要的"边界":一把尺子,一刀切清

现在你手里有塔了。但你最初的问题里点名要"边界是什么"——harness 往下到哪算模型、往上到哪算入口皮,旁边那个火到爆的 MCP、那些工具和 skill,又插在它身上的什么位置?

好消息是:**有一条线能一刀切清。坏消息是它太简单,简单到你会怀疑——但它真的够用:**

> **谁握着那支笔——谁拥有「循环」、并拥有「往上下文窗口里写什么」的权力,谁就是 harness。**

拿这把尺子去量,三条边界自己就清楚了:

- **往下 ↓ 模型不算 harness。** 模型只在"被喂进来的那一屏字"上做一次失忆补全,它不拥有循环、也决定不了下一屏写啥。**分界就在那一次 API 调用上**:调用之内(把字发给云端、拿回答案)是模型的活;调用之外那个一圈圈转的循环,是 harness 的活。

- **往上 ↑ CLI/网页不算 harness,它们是"皮"。** 同一套 harness,你从终端进、从网页进、还是像你这套从飞书进,**循环逻辑一个字不用改**。能被整块换掉而内核不动的,按定义就不是内核——它是皮。(你把 Hermes 削成"薄传输",它就是张皮的活样本。)

- **往旁边 ↔ MCP/工具/skill 不算 harness,它们是"外挂"。** 这条最容易被 MCP 的热度搞混,所以用官方原文钉死:**MCP 官方自己声明,它"只管工具和数据怎么标准化地递进来这套接口协议,明确不规定 AI 应用怎么用模型、怎么管上下文"**。也就是说,**MCP 在设计上就把"循环+上下文写权"原封不动留给了 harness**(官方把跑循环的那个应用叫 MCP Host,点名就是 Claude Code 这类)。工具表是 harness 拉过来汇成一张清单的,要不要调、结果写回哪一屏,也是 harness 拦下来路由的。MCP 再火,它也是**插在 harness 身上的外挂**,不是那只手。

那几个灰色地带呢?**system prompt 怎么拼、记忆回填哪几条、子 agent 拆几个各喂什么**——用这把尺子一量就清楚:它们全都是"在循环的每一拍,决定往那一屏字里写什么",**全是握笔的手,所以是 harness 内核。**

**这条边界对你团队的直接落点(决策):**

| 层 | 是什么 | 你团队该怎么对待 |
|---|---|---|
| **内核**(循环、上下文拼装、记忆选取、子agent编排) | 握笔的手 | **重投工程力**——这是体验和护城河所在(但下一节会告诉你一个反转) |
| **外挂**(MCP/工具/skill) | 供货的能力 | **主要接标准**——接口做干净、即插即用就够,别造轮子 |
| **皮**(CLI/网页/飞书) | 搬运人话 | **做适配**——多端复用同一内核,别让某个入口把循环绑死 |

*来源:MCP 官方架构与边界声明(modelcontextprotocol.io/docs/learn/architecture);harness=包住模型的完整基础设施、模型是其中最小一块(MongoDB 工程博客,2026);Claude Code 子 agent 独立上下文窗口(code.claude.com/docs/en/sub-agents)。注:"harness"业界没有标准组织的统一定义(也叫 agent runtime / scaffold),这条"循环+写权"切分线是综合多个权威来源后的判断,不是某份官方文档原话——但它和所有来源自洽,且能干净处理灰区。*

## 四、最绕的那个词:"agent"到底指啥?

这堆词里,"agent"歧义最大——一会儿指整个跑起来的系统,一会儿指你用 Task/worker **派出去的一个个小兵**。难怪绕。

但拆开看,它俩其实是**同一个结构的两个尺度**,看懂这点,绕就解了:

- **广义 agent = 整套在跑的系统。** 一个模型 + 一套工具 + 一个目标,在循环里**自己决定下一步干啥**(而不是照写死的剧本走)。你的墨菲斯 worker,整体就是这么一个 agent。
- **子 agent(subagent)= 这套系统在干活中途,临时雇的一个"带独立脑子的临时工"。** 它本质上**就是:主系统再开一个空白、干净的第二个"上下文窗口",塞给它一个子任务,它自己在那个窗口里翻江倒海,跑完只把一句结论递回来,然后回收。**

这里有个你必须抓住的画面:**一个 agent 一次能看进眼里的全部东西——它查过的网页、读过的文件、纠结过的废稿——全挤在一个叫"上下文窗口"的盒子里,而这盒子是有限的。** 要是让一个 agent 自己顺着查 5 个问题,盒子很快被 5 摊中间垃圾塞爆,它对全局的判断力就糊了。

子 agent 就是来解这个的,它一招治两个病:
1. **主 agent 的盒子永远干净**——临时工的翻页过程全留在它自己的盒子里,主 agent 只拿回那一句结论,不沾垃圾;
2. **临时工能同时开干**——5 个一起跑,不用排队,快。

**而这套结构,正是你这份报告本身的生产方式——这不是巧合,是活例子:**

> 你的 morpheus-worker 写死了"第一铁律:必须组建专家团队,严禁单干"。刚才我(主 agent,当**总编**)就给这 5 个问题各派了一个**专家(子 agent,当各跑各线的记者)**,他们在**各自独立、干净的盒子里**联网、钻研、试错——那些翻了几十页的过程,我这边一点没沾,我手里只攒了 5 份干净的判断。这就是为什么我汇总时脑子是清楚的,还能让 5 个人**并行**把活干完。**一个总编,带着一群各有独立脑子的记者**——这就是"多 agent 编排"褪去术语后的真身。

**判断:** "agent"两层意思——大的是"整个系统在跑",小的是"系统跑的过程中临时开的一个隔离窗口"。子 agent 的本质,**就是隔离开的、干净的第二个上下文窗口**。看懂这一层,你以后再读任何"多 agent 编排",看到的不再是一堆术语,而是一个总编带一群记者。

*来源:agent 定义(Anthropic《Building Effective Agents》);子 agent"runs in its own context window … returns only the summary"(Claude Code 官方文档);主从并行、多 agent 比单 agent 强 90%+(Anthropic《How we built our multi-agent research system》)。注:严谨对外引用时,"上下文污染"宜用官方词"flood the main conversation / prevent context overflow"。*

## 五、下注:模型谁都能调,那护城河到底在哪层?该押哪?

前四题给了你地图。这一题是给产品人那只手的真问题——也是你最该带走的一题。

现在这个局:模型谁都能调,Claude Code、Cursor、Codex 底下那台发动机其实差不多。**那它们卷什么?卷的是发动机外面那套传动系统——也就是 harness。** 而且这层是真值钱,有个实测能钉死:

> **同一个模型,光改外面这套 harness 架构,在编程测试上能涨 13 分(LangChain,Terminal-Bench),比换一代新模型涨得还多;换 harness 在 SWE-bench 上改 22 分,换模型只改 1 分。**

所以 2026 全行业都在喊"模型是燃料,harness 才是护城河"。到这儿你大概会点头——**但别停在这儿,这正是要拆穿的地方。**

**反转一:这条护城河是谁的?——是 Anthropic 的,不是你京小贝的。**

发生了一件很反直觉的事:**Anthropic 把自己这套最值钱的 harness,打包成一个谁都能免费装的 SDK 发出去了**(Claude Agent SDK,昨天还是 Claude Code 的护城河,今天变成谁都能 `pip install` 的地基);同时,agent 接工具那套接口(MCP),已经被它**捐给了 Linux 基金会**,OpenAI、谷歌、微软一起站台,变成了像 USB 口一样的公共标准。翻译成生意话:**昨天的护城河,今天被官方亲手填平,变成了所有人脚下的免费水泥地。**

那为什么还有人说 harness 是护城河?——因为对**造模型的实验室**它确实是:模型是专门针对自家 harness 调教出来的,两者一起进化,外人追不上。**可这恰恰说明:这条护城河属于 Anthropic/OpenAI,不属于你。你不造模型,拿不到这层红利;你能拿到的那部分 harness,是被免费送给你、也送给字节豆包的公共品。**

**反转二:那护城河迁到哪了?——不在你以为的 prompt/skill 那层。**

你是 prompt/skill 老手,本能会觉得"价值都在 prompt/skill"。但**prompt 和 skill 是世界上最容易被复制的东西**:你能写的金融话术,豆包团队照样写,官方 SDK 还会把通用能力直接内置。**话术不是护城河。**

护城河迁到了两个地方,都很"段永平"——看的是生意最底层那点不可替代的东西:

1. **数据,但不是你导进来的公开数据,是你的产品独家"制造"出来的数据。** a16z 那句话你该记住:*有防御力的数据,是你的产品独家生出来的数据*——用户在京小贝面前暴露的真实财务状态、面对涨跌的真实反应、改主意的时点、被哪句话说服。**这些是通用大模型这辈子都拿不到的,因为只有当用户把京小贝当成管钱的"记账本"(system of record),这些数据才会被生出来。**

2. **在金融这行,合规边界本身就是护城河。** "perimeter is the moat"——监管已经把金融 AI 列为高风险、强制可追溯。这意味着"会算账"不值钱,"算得对、说得清、过得了监管"才值钱;**这道墙挡住的不是用户,是竞争对手。**

**所以,给京小贝的押注方向(这是结论,不是综述):**

> **别去自建通用 harness。** 那是在 Anthropic 有结构性优势、还在把成本打到零的战场上砸重资产——巴菲特/段永平最忌讳的赔本买卖,你自建的工程力半年内会被一次官方 SDK 升级抹掉。
>
> **站在标准 harness 上(Claude Agent SDK 或其上的自有薄壳),把团队全部工程力压在三件事:**
> 1. **数据飞轮(最高优先级,真护城河):** 把京小贝做成京东金融用户财务的**记录系统**,转动那个只有你转得动的数据飞轮——你最大的资产不是 skill,是你独家观察到的"中国大众用户面对钱时的真实人性反应";
> 2. **金融 skill + 合规边界焊死:** skill 值钱的不是话术,是它和合规绑死、可审计、过监管的那一截——让"靠谱"成为别人抄不走的资产;
> 3. **吃满京东分发:** 把 agent 深度嵌入京东金融现有工作流——这是字节要花几年买、你天生就有的东西。

## 收束:回到开头那把枪

我们从一个别扭感出发:你把六个词并排摆着比大小,总觉得哪里不对。

现在你知道哪里不对了——**它们不在一个层。** 最底是缸里那颗失忆的脑(模型);套在它外面、一圈圈把它救活、决定每圈喂它什么的那层身体,叫 **harness**;身体外面那张可以随便换的脸,是 CLI/网页/飞书(入口);而你最熟、打磨了多年的 prompt 和 skill,是**喂进这个身体嘴里的子弹**。你一直活在"上下文窗口里面"打磨弹药,从没回头看过——**是谁在一轮轮地泵这个窗口?那个泵,就是 harness。**

这张图就是坐标系:以后任何一个 AI 工程的词砸过来,你先问一句"它是脑、是身体、是脸、还是喂进去的内容",它就有地方搁了。

而那扇你现在能推开的新门是:**harness 虽是这两年的护城河,却是别人在守的城;你京小贝真正的金矿,不在跟人卷 harness,而在你脚下——用户每天在你这儿管钱时,替你挖出来的那堆独家数据,和你用合规为它砌起来的那道墙。**

## 还没压实的(诚实交底)

这份报告里,前四题(塔的结构、模型缺什么、边界、agent 两义)是**机制层面的确定结论**,有 Anthropic / MCP / Claude Code 官方文档逐条坐实,你可以当地基用。下面几条是我没把握十足、或需要你自己校准的,单独挑出来:

1. **【最软的一环】"通用 harness 长期沦为 commodity"是趋势推断,不是定论。** 方向证据很硬(官方 SDK + MCP 标准化 + 可热插拔 harness 三箭齐发),但"沦为 commodity 到什么程度、多快"是推测。我采纳了反方观点并据此推出"对应用层=commodity、对实验室=护城河"这个区分——**这个区分是我的判断,不是哪篇文章的原话。**

2. **【需要你内部验证】"京小贝独家数据是最大资产"是把 a16z 通用框架套到京小贝的推断。** 我手里没有京小贝实际的数据资产盘点——**你们到底沉淀了哪些公开模型拿不到的数据?那个闭环真转得动吗?** 这条最该你拿内部事实去验,我只能给方向。

3. **【二手、未实测】Codex vs Claude Code"内核层 vs harness 层强制权限"这条机制对照,来自搜索聚合,未经一手实测。** 方向可信,但金融场景选型前,建议你团队亲手跑一遍两者的沙箱/权限模型再定。

4. **【术语】"harness"业界没有标准组织的统一定义**(也有人叫 agent runtime / scaffold / 智能体框架)。本报告"谁握循环+上下文写权,谁就是 harness"这条切分线,是综合多个权威来源后的判断,自洽且好用,但不是某份规范的原文。

5. **【小推断】OpenClaw 的分层归类**(harness/身体)是基于其已知功能做的架构推断——这个具体产品没有公开资料可引。Hermes 那条相反,有你自己项目代码作硬证据。
